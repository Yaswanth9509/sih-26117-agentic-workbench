How This Works

A plain-English walkthrough of the problem, the solution, and why it matters — no engineering background required.

1THE PROBLEM

Maintenance decisions are hard to get right — and hard to defend

Every day, engineers at a refinery like MRPL have to decide: service this equipment now, or wait? That call is usually made from memory, paper logs, and gut feel — not because anyone is careless, but because cross-checking safety limits, cost, and history by hand for every decision simply doesn't scale.

Service too early

Money wasted

Healthy equipment gets taken offline and serviced anyway — unnecessary cost, unnecessary downtime, for no real safety gain.

Service too late

Safety at risk

A warning sign gets missed or under-weighted — and the result can be an unplanned shutdown, equipment damage, or a safety incident.

💡 There's a third, quieter problem: even when the right call is made, there's often no clear record of why — which matters the moment a regulator, auditor, or new engineer asks.
2THE SOLUTION

Ask a plain-English question. Get a validated, explainable answer.

An engineer types a normal question — the way they'd ask a colleague — and gets back a structured recommendation in seconds. Not a guess: an answer that's been checked against real safety and cost rules, with the reasoning shown, and permanently logged.

3HOW IT WORKS, UNDER THE HOOD

Five specialized checks, run automatically, every time

Instead of one AI model guessing an answer, the question passes through five focused steps — each one doing a single job well. No step trusts the previous one blindly.

🛡️
Before any of it runs: the question is screened for malicious input and each engineer is rate-limited. Nothing reaches the AI until it has passed that gate.
🧭

1. Understand

Reads the question — figures out which equipment, and what's really being asked.

🔍

2. Look Up

Searches the real equipment records for facts relevant to this exact question.

🧠

3. Reason

An AI model thinks through the situation the way an experienced engineer would.

✅

4. Check

Runs the answer against 5 hard safety, cost and compliance rules — no AI opinion is trusted blindly.

📋

5. Decide

Combines everything into one clear recommendation — logged permanently for audit.

⏱️
Every step is independently time-limited. If any one stage is slow, it is cut off and handled — a single slow step can never hang the engineer's request.
🔒
Runs entirely on local hardware. No company data ever has to leave the plant network to get an answer — the AI model itself runs on-site.
4WHAT IF THE AI FAILS?

It never comes back empty-handed

Step 3 is the only step that uses an AI model — and AI models can be slow, overloaded, or simply switched off. So the system has a chain of backups. It tries each in order and uses the first one that answers.

🖥️

Mistral, running on-site preferred

A full AI model running on the plant's own GPU. Nothing leaves the building. This is the intended production setup.

↓ if unavailable or too slow
☁️

Cloud AI optional

Only used if someone deliberately configures a key — a convenience for demos on a laptop with no GPU. Every decision records that cloud was used, so it is never ambiguous.

↓ if unavailable or too slow
⚙️

Rule-Based Engine always works

A deterministic engine written in plain code — no AI, no network, no GPU. It cannot fail, cannot be slow, and cannot be unavailable. This is the floor beneath everything.

🔌 Circuit breaker: if a provider fails repeatedly, the system stops waiting on it entirely and serves answers instantly from the engine below it — rather than making every engineer wait out the same timeout. It automatically retries after a short cooldown, so a temporary problem heals itself with nobody having to restart anything.
✅ The result: a request can never fail. There is always a valid, validated answer.
5WHERE THE DATA LIVES

Three simple stores — and deliberately no database

A common question: what database is behind this? The honest answer is none — and that's a design decision, not a shortcut.

📄

Equipment records

The source of truth: specifications, service schedules, past repair logs, safety limits and costs. Plain files an engineer can open and read.

data/sample_docs/
🔍

Search index

So the system can find the right facts by meaning rather than exact wording. A lightweight local index, rebuilt from the records in seconds — not a separate database server to run and maintain.

data/tfidf_index.pkl
🧾

Audit trail

Every decision ever made, one per line, only ever added to — never edited, never overwritten, never deleted.

data/audit_logs/decisions.jsonl
Why no SQL database? Nothing here needs one. There are no user accounts, no transactions, no concurrent writers competing over rows. Avoiding a database means there is no extra server to install, secure, back up, or keep running inside a refinery's network — and every piece of data stays a file that can be inspected, copied, or handed to an auditor directly.
6THE AUDIT TRAIL

Every decision leaves a permanent record

The moment a recommendation is produced, it is written to a log that is only ever appended to. This is what turns "the AI said so" into something an auditor or regulator can actually verify months later.

decisions.jsonl — one line per decision 
{
  "timestamp":         "2026-09-04T07:15:44Z",
  "decision_id":       "DEC-20260904-071543",
  "user_id":           "engineer_1",
  "equipment":          "reactor-4",
  "recommendation":     "Schedule Maintenance",
  "validation_status":  "APPROVED",
  "compliance_score":   100,
  "engine_used":        "ollama",
  "total_time_ms":      6089
}
Append-onlyEntries are never edited or removed, so the history cannot be quietly rewritten after the fact.
Names the engineEach entry records which engine produced it — local AI, cloud, or rule-based — so accountability is never ambiguous.
Answers "why?"Months later, anyone can look up exactly what was recommended, on what basis, and whether it passed every check.
7WHERE ELSE THIS APPLIES

The same pattern works anywhere a decision needs to be fast and defensible

This isn't a one-refinery tool. It's a general pattern: ground every answer in real records, validate it against hard rules, and log everything — wherever a costly or safety-critical call has to be made quickly.

🏭

Oil & Gas / Refining

Equipment maintenance, safety compliance, turnaround planning.

⚡

Power Plants

Turbine and grid-asset servicing decisions under strict uptime pressure.

🏗️

Manufacturing

Production-line equipment, minimizing costly unplanned stoppages.

✈️

Aviation MRO

Maintenance, repair & overhaul decisions with zero tolerance for error.

💧

Utilities

Water treatment, pipelines — assets that are expensive to inspect manually.

⛏️

Mining

Heavy machinery in remote, connectivity-poor sites — sovereignty matters most here.

The core idea — grounded retrieval + rule-based validation + audit trail — generalizes to any regulated, asset-heavy operation, not just this one.
